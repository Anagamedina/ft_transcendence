AquaGuard · plan de decisión

Cómo enfocar el bonus sin poner en riesgo la entrega

El bonus debe ampliar un producto ya demostrable. No debe convertirse en una segunda aplicación independiente ni desplazar el Mandatory o los 14 puntos base.

Puertas que deben cerrarse

PUERTA 1

Mandatory

Auth, multiusuario, validación, HTTPS, legal, responsive, DB y README.

PUERTA 2

Flujo vertical

Simulador → API → PostgreSQL → API → Vue, con lecturas e históricos.

PUERTA 3

14 puntos

Los módulos planificados deben estar completos y demostrables, no solo scaffolding.

PUERTA 4

Bonus

Agregar módulos extra con valor de producto y justificación explícita.

Situación actual detectada: auth register/login, sites/sensors, histórico, alertas, dashboards y simulador aún tienen partes pendientes o no verificadas. Activar bonus ahora fragmentaría el foco.

Selección propuesta para AquaGuard

Recomendación:

Elegir detección de anomalías como el bonus principal porque extiende directamente el dominio de sensores, lecturas y alertas. Después completar tres minors de bajo acoplamiento: PWA/push, health/status/backups e i18n.

Detección de anomalías

Custom Major · 2 puntos
Prioridad 1
Encaje
95%
  • Ventanas temporales y tendencia progresiva, sin necesidad de ML complejo.
  • Explica por qué una lectura es anómala y la relaciona con el sensor.
  • Demo clara: el simulador inyecta patrones y el backend genera una alerta.
Riesgo: al ser custom, justificar alcance, complejidad y valor en README y validarlo con evaluadores.

PWA + notificaciones push

Minor · 1 punto
Prioridad 2
Encaje
88%
  • Instalación móvil, app shell offline y recuperación de red.
  • Push para alertas críticas de sensores.
  • El push aporta valor, pero el punto procede del módulo PWA.
Dependencias: auth, alertas y configuración segura de VAPID.

Health/status + backups

DevOps Minor · 1 punto
Prioridad 3
Encaje
90%
  • Extiende los health checks existentes con estado operativo útil.
  • Backup PostgreSQL automatizado, restauración probada y retención.
  • Página de status con DB, backend, gateway y última copia.
Ventaja: aporta evidencia operativa sin cambiar el dominio funcional.

i18n ES/EN/CA

Multiple languages Minor · 1 punto
Prioridad 4
Encaje
76%
  • Al menos tres traducciones completas y selector visible.
  • Todo texto de usuario debe pasar por claves traducibles.
  • Fechas, números y mensajes de error con formato por idioma.
Condición: no iniciarlo hasta estabilizar las pantallas finales para evitar traducir UI provisional.

Alternativas que no recomiendo como primera opción

SMS a móvil

Custom Minor · posible 1 punto
Solo si se valida antes
  • Requiere proveedor externo, secretos, costes y pruebas de entrega.
  • El subject no lo lista como módulo estándar.
  • Hay que acordar previamente que el alcance merece un custom Minor.

Chat Admin-Cliente

User interaction Major · 2 puntos
Mucho riesgo
  • No es solo enviar mensajes: exige chat, perfiles y sistema de amigos.
  • Introduciría un dominio nuevo, WebSockets y más permisos.
  • No encaja con la ruta crítica de monitorización.

Orden de implementación recomendado

Bloque A
Mandatory y flujo vertical

Terminar auth, endpoints de sites/sensors, histórico, alertas, dashboards, simulador y verificación de Compose.

Bloque B
Cerrar contrato de integración

Mock y API real con el mismo JSON, tests de errores y una demo completa desde lectura simulada hasta Vue.

Módulos core
Real-time, permissions, organization, analytics

Completar los Major que ya están en el plan de 14 y después search, export/import y notifications.

Cierre
Validación del evaluador

Solo marcar puntos con código funcional, pruebas, recorrido reproducible y contribuciones documentadas.

Modelo
Definir anomalía explicable

Combinar umbrales configurados, media móvil, desviación y persistencia temporal. El resultado debe explicar sensor, ventana y causa.

Producto
Alerta y visualización

Persistir evento, mostrar severidad y evidencia en dashboard, y permitir reconocer/resolver sin duplicar alertas.

Demo
Escenarios del simulador

Normal, presión baja/alta, deriva gradual, picos y recuperación. Añadir tests para falsos positivos básicos.

PWA
Instalación y offline shell

Manifest, service worker, iconos, caché de la app shell y estado de conexión visible.

DevOps
Status y recovery

Endpoint status, backup programado, restore probado y documentación de recuperación.

i18n
ES, EN y CA

Extraer todos los textos, selector, traducciones completas y pruebas de cambio de idioma.
