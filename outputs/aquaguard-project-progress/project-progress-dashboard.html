Errores y coherencia del backend

La separación router → service → repository → modelo es una buena base y el flujo de lecturas/alertas funciona en casos normales. Sin embargo, el backend no está completo ni puede considerarse totalmente coherente: hay errores reproducidos, riesgos de concurrencia y contratos todavía sin integrar.

Recomendación de arranque mantenible
  1. make setup/doctor: validar Docker, Compose, variables requeridas y puertos; no sobrescribir .env existente.
  2. make dev: preparar certificados → build → PostgreSQL healthy → upgrade head único → API ready (/api/health/db) → gateway.
  3. migration-check explícito: comprobar revisión actual contra head y ejecutar alembic check en entorno de desarrollo/validación; fallar con explicación si hay drift.
  4. make seed explícito solo en desarrollo; confirmar sensores/config del simulador antes de make sim.
  5. make smoke: login, lectura con UUID, reintento, alerta tenant e histórico; comprobar persistencia tras reinicio.
Nunca generar ni aplicar una revisión autogenerada sin revisión humana. Alembic check no crea migraciones y no sustituye upgrade head. Añadir targets pequeños que deleguen en scripts para validación, migraciones y smoke; CI sigue siendo opcional para el cierre Mandatory.
